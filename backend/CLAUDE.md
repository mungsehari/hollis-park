# Hollis Park store API (backend)

Spring Boot 3.5 / Java 21 REST API. Spring Security with a session cookie + CSRF (sessions in Postgres via
Spring Session JDBC), JPA/Postgres with Flyway, S3 for images, Razorpay for payments. Runs on ECS Fargate
next to the nginx container that serves the store and the admin panel.

## Layout

```
com.hollispark.store
  config/       security, CORS, cache, OpenAPI, media storage, Access (the @PreAuthorize rules)
  controller/   one package per area: catalog, order, payment, marketing, content, auth, admin
  service/      business logic, same areas (+ dashboard, settings, user)
  repository/   Spring Data repositories, same areas
  entity/       JPA entities; every one extends entity/base/BaseEntity
  dto/          request/response records, one per file, same areas; dto/ApiResponse is the envelope
  enums/        every enum (stored as STRING, each has a CHECK constraint in the schema)
  exception/    AppException + one subclass per HTTP outcome, and GlobalExceptionHandler
  filter/       request id, rate limits, HTTP caching
  client/       outbound partners (Razorpay)
  storage/      local folder or S3 for uploaded images
  startup/      first-start seed data
  util/         small helpers (paging, writing error bodies outside MVC)
```

Controllers stay thin: validate the body (`@Valid`), call one service method, wrap the result in
`ApiResponse`. Repositories are used from services, not from controllers.

## API conventions

- Every route is under `/api/v1` (except `/media/**`, which serves images).
- Every JSON answer is `ApiResponse`: `{success, status, message, data[, requestId]}`. Lists that page use
  `dto/base/PaginationDto` (`content, pageNumber, pageSize, totalElements, totalPages, last`).
  The only non-envelope responses are files (`/api/v1/admin/subscribers/export`), images and the
  `/api/v1/go/...` redirects.
- Admin endpoints declare their role with `@PreAuthorize(Access.STAFF)` / `@PreAuthorize(Access.ADMIN)`
  **and** the same rule exists as a URL rule in `SecurityConfig`. The URL rule runs before the body is
  parsed, so a STAFF user gets 403, never a validation message. Change both together.
- API description: `/api/v1/docs`, Swagger UI: `/api/v1/docs/ui` (off in production).

## Error handling

**Read [docs/error-handling.md](docs/error-handling.md) before touching any failure path.** In short:

- A client mistake is never a 500. Throw `BadRequestException`, `ResourceNotFoundException`,
  `ConflictException`, ... never a raw `RuntimeException` or `IllegalArgumentException`.
- A 5xx never returns the exception's message. Log the detail once (GlobalExceptionHandler does it),
  give the client a generic sentence.
- There is exactly one `@RestControllerAdvice` (GlobalExceptionHandler) plus `ApiErrorController` for
  `/error`. Do not add another.

## Data model: things that bite

- **UUID primary keys everywhere** (`BaseEntity`), generated by the application. Anything people type or
  link to keeps its own unique column: product / collection `slug`, promo `code`, page `pageKey`.
  Customers see order numbers (`HP-24001`, from `order_number_seq`), never UUIDs.
- **`@Version` on every row.** A stale save throws an optimistic-lock failure → 409. Load, change, save
  in one transaction; never build an entity from a request and `save()` it over an existing row.
- **`ddl-auto: validate`.** The schema is owned by Flyway; an entity/column mismatch stops the app at boot.
- **Payment confirmation and the Razorpay webhook can arrive together.** Both lock the order row
  (`lockByOrderNumber` / `lockByRazorpayOrderId`); keep it that way.
- **The storefront reads from a cached snapshot** (`StorefrontService`). Any admin write that changes
  what the store shows must call `storefront.changed()`.

## Migrations

`db/migration/V1__init_schema.sql` is the whole base schema; each change is a new `V<n>__...sql`.
Flyway validates on start, so **never edit or delete a migration that has run anywhere** (including a
teammate's laptop or the RDS database).

## Build and test

```
mvn -q -DskipTests compile
mvn test        # all tests run against an embedded PostgreSQL (zonky), no Docker needed
```

Every change to `src/main/java` comes with tests. `ApiContractTest` pins the response envelope and the
4xx rules. For a migration that changes existing data, add a test that migrates to the previous version
with Flyway's `target`, inserts rows, migrates to the latest and checks them.
